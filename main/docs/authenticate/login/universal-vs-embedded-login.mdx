Auth0 supports two fully supported, production-ready approaches to authentication: Universal Login (hosted by Auth0) and Embedded Login (hosted by you). The right choice depends on your application’s specific requirements for user experience, customization, and implementation effort.

## Universal Login

In a hosted login flow, the application redirects the user to the <Tooltip tip="Authorization Server: Centralized server that contributes to defining the boundaries of a user’s access. For example, your authorization server can control the data, tasks, and features available to a user." cta="View Glossary" href="/docs/glossary?term=authorization+server">authorization server</Tooltip> to perform authentication, and then the authorization server returns the user to the application.

### How it works

1. Your application triggers an authentication request by invoking an Auth0 SDK’s login method or by calling the [Auth0 Authentication API Login endpoint](https://auth0.com/docs/api/authentication/login/) directly.
2. Your application redirects the user to the Auth0 authorization server (your Auth0 tenant).
3. Auth0 checks for a session cookie on the [Auth0 Session Layer](/docs/manage-users/sessions/session-layers).

   * If a session cookie is not found, Auth0 redirects the user to Universal Login to authenticate and creates an associated session cookie.
   * If a session cookie is found, Auth0 uses it to authenticate the user.
4. Auth0 returns the user to your application with an [ID token](/docs/secure/tokens/id-tokens) and an [access token](/docs/secure/tokens/access-tokens).

### When to use Universal Login

* You want Auth0 to manage security updates and new features automatically
* You need SSO across applications on different domains or with third-party applications
* You prefer centralized configuration through the Auth0 Dashboard

## Embedded Login

In an embedded login flow, the user authenticates directly within your application. Your application serves the login form, collects the user’s credentials, sends that data to Auth0, and receives back the user’s <Tooltip tip="ID Token: Credential meant for the client itself, rather than for accessing a resource." cta="View Glossary" href="/docs/glossary?term=ID+token">ID token</Tooltip> and <Tooltip tip="ID Token: Credential meant for the client itself, rather than for accessing a resource." cta="View Glossary" href="/docs/glossary?term=access+token">access token</Tooltip>. All authentication logic and security handling are managed by Auth0 SDKs and APIs; you control only the UI presentation and flow.

For web applications, use a [custom domain](/docs/customize/custom-domains) to keep authentication on the same top-level domain as your application for the best user experience and session handling.

### When to use Embedded Login

* You need complete control over the login UI to match your application’s exact design system
* You want users to remain in your application throughout authentication without redirects
* You are building a native mobile app and want to avoid browser redirects
* You need custom authentication flows such as progressive profiling, step-up authentication, or multi-step challenges
* You are integrating authentication into non-traditional interfaces (AI agents, chatbots, checkout flows)

<tr>
<td><strong><a href="/docs/authenticate/single-sign-on">Single Sign-on</a></strong></td>
<td>Built-in across all applications and domains through <a href="/docs/manage-users/sessions">session cookies</a> on the Auth0 Authorization Server.</td>
<td>Supported across first-party applications with a <a href="/docs/customize/custom-domains">custom domain</a>. Use <a href="/docs/libraries/lock/lock-api-reference#checksession-">Lock</a> or <a href="/docs/libraries/auth0js#using-checksession-to-acquire-new-tokens">Auth0.js</a> for web apps, or <a href="/docs/authenticate/single-sign-on/native-to-web">Native to Web SSO</a> for native apps.</td>
</tr>
<tr>
<td><strong><a href="/docs/customize">Customization</a></strong></td>
<td>Configurable through Dashboard (theming, templates, text) and <a href="/docs/customize/login-pages/advanced-customizations">Advanced Customizations</a> for deeper control.</td>
<td>Complete control over UI/UX. Build any login experience using your own components and design system.</td>
</tr>
<tr>
<td><strong>Feature updates</strong></td>
<td>Managed centrally by Auth0. All changes apply immediately across all applications.</td>
<td>Managed by you in your application code. You control when and how to adopt new features.</td>
</tr>
<tr>
<td><strong>User experience</strong></td>
<td>Users are briefly redirected to Auth0 Authorization Server during authentication. Native apps require universal/deep links to return.</td>
<td>Users remain in your application throughout authentication. No redirects or context switching.</td>
</tr>
<tr>
<td><strong>Implementation effort</strong></td>
<td>Lower effort. SDK handles redirects and callback logic; less code to write.</td>
<td>Higher effort. You build and maintain the login UI and orchestrate the authentication flow.</td>
</tr>
<tr>
<td><strong>Security</strong></td>
<td>Auth0 manages all security updates and threat mitigations automatically.</td>
<td>Auth0 SDKs and APIs handle all protocol-level security. You are responsible for UI-layer security best practices (e.g., secure credential handling, injection prevention).</td>
</tr>
</tbody>
</table>
